# New Simple Way Plan (KISS)

## Goal
Reimplement a minimal EA backtesting workflow that works with a local MT5 install and stays portable (Devbox + Docker). Keep MT5 on the host; Docker is for analysis only.

## Observations From Current Repo
- The current approach tries to run MT5 inside a container (Wine + heavy bash), which is brittle and hard to debug.
- Backtest orchestration and parsing are spread across many scripts; too complex for KISS.
- The repo already contains useful MT5 config templates in `conf/`, but the execution path is overbuilt.

## Proposed Minimal Architecture
- Host MT5 (Windows now, Linux/Wine later).
- Small Python "bridge" on the host to prove connection and collect basic info.
- Dockerized analysis that reads exported reports (HTML/CSV) from a shared folder.
- A single `data/` folder for reports and connection proofs.

## Plan
1. Connect and prove MT5 connection (must be first).
   - Add `simple/bridge/mt5_probe.py` using the `MetaTrader5` Python package.
   - Add `simple/config/.env` with terminal path and optional login/server.
   - Run inside Devbox and confirm:
     - `mt5.initialize()` returns true
     - `mt5.terminal_info()` and `mt5.version()` are non-null
     - Write `data/connection-proof.json` with timestamp, terminal version, and account id
   - Success criteria: `data/connection-proof.json` exists and shows live MT5 info.

2. Minimal backtest export flow (manual first).
   - Run a Strategy Tester backtest in MT5 UI with a known EA.
   - Export the report as HTML or CSV into `data/reports/`.
   - Add `simple/analysis/parse_report.py` to extract key metrics (net profit, drawdown, trade count).
   - Success criteria: the parser prints the expected metrics for a chosen report.

3. Dockerized analysis (read-only MT5).
   - Add `simple/analysis/Dockerfile` with Python + analysis deps.
   - Mount `data/reports/` into the container and run the parser inside Docker.
   - Success criteria: container output matches the host parser output.

4. Optional automation (only if needed).
   - Use MT5 command line `/config` for headless runs, or Windows UI automation.
   - Store generated reports in `data/reports/` with deterministic file names.
   - Success criteria: script starts MT5, backtest completes, report created.

5. Cross-platform checks.
   - Document Windows vs Linux MT5 data/report paths.
   - Ensure `.env` and volume mounts work on both OSes.

## Devbox + Docker Baseline
- `devbox.json` for a host Python environment (Windows/Linux).
- `requirements.txt` for `MetaTrader5`, `pandas`, `numpy`.
- Docker is only for parsing and analysis, not for running MT5 itself.

## Proposed New Layout

  reports/
